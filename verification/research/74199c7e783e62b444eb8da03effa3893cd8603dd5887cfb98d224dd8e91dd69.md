## 1. Replacement precedence

Original function `0x560230..0x5602A9` takes a path and an output archive index.
It computes mounted count from `(this+0x4C - this+0x48)/20`, begins with index
zero, and calls the index-tree lookup at `0x598D50` using each record's `+8`
pointer. At `0x560268`, a nonzero lookup result immediately branches to success
at `0x56029B`. On failure it increments the archive index and adds 20 to the
record offset at `0x560275..0x560278`. Success returns the found file record and
writes the first matching vector index to the caller's output pointer.

Exact relevant original bytes:

- `0x560253`: `33 F6` (start record offset at zero).
- `0x56025F`: `E8 EC 8A 03 00` (call index-tree lookup).
- `0x560268`: `75 31` (first nonzero result goes to success).
- `0x560275`: `43 F7 E9 83 C6 14` (increment index, multiply, advance record).
- `0x56029B`: `8B 45 0C 5F 5E 89 18 8B C1 5B 5D C2 08 00`.

This is used by existence checking (`0x55FC45`), size lookup (`0x55FDEA`),
and the archive-backed file opening path (`0x5979A8`). The last caller uses the
returned vector index to select the archive context at `0x5979E8..0x597A05`.
Thus it is not merely a directory-listing order.

## 2. Actual livery target and slot sharing

Decoded the original GFCF v3 `scripts/config/paint_PC.cfg` using the layout in
`NativeLinux/archive.hpp`. ALF has nine packs; zero-based pack 6 (`alfPack7`,
price 7500) uses numeric livery 1. Packs 7 and 8 (`alfPack8`, `alfPack9`) both
use livery 2. Packs 0 through 5 use livery 0. Availability in the owner's save
has not been checked or changed.

Consequently, replacing `alf_02` affects **two paint selections**, not one.
The editor must list all packs sharing a chosen resource. The initial target
should be ALF livery 1, subject to its availability for visual testing. Do not
promise arbitrary single-slot isolation without config changes.

`gaVehiclePaintManager.applyChosenPaintPack` in the local ILSpy output uses the
saved pack index and constructs `vehicles/decals/%s_%02d`. Original executable
string VA `0x9FC274` is `graphics/%s/batchTextures.brres`; its native formatting
sites include `0x494DC8` and `0x50766C`. These corroborate the archive naming,
but this pass has not traced every virtual dispatch from paint selection to
that formatter or proved the texture is bound to the intended shader sampler.

The original ZIP contains exactly:
`graphics/vehicles/decals/alf_01/batchTextures.brres` (case retained here).
Its TABT contains one texture, named `alf_01`.

| Dimensions | Format | DDS mip-count field | Batches |
| --- | --- | --- | --- |

For all 30, payload size exactly equals the 128-byte DDS header plus the
block-compressed levels. Zero mip-count has one stored level in these assets;
do not interpret it as an empty image. Checked each size with 16 bytes per
4×4 block, rounding each dimension up to blocks with a minimum of one block.
The archive member spelling contains uppercase `T`, whereas the existing
Python writer insists on lowercase paths. Follow-up native tests resolve this:
use lowercase `batchtextures.brres` in generated indexes/ZIPs. Low-level lookup
uses lowercase backslash-separated paths; mixed-case lookup failed in the fixture.
Do not assume case-insensitive index matching.

## 3. Round-trip and import acceptance requirements

These are proposed implementation requirements, not claims of implemented tests:

- No-op means extracted TABT bytes and embedded DDS bytes match the original
  SHA-256 exactly. Do not decode/recompress unchanged DDS. ZIP compression,
  timestamps and rebuilt offsets may differ; those are not asset-byte changes.
- A changed export preserves batch metadata, names, entry order, all unrelated
  payloads, DDS format/dimensions/caps and the selected original mip layout.
  For ALF livery 1, regenerate all eleven levels after an artwork edit. For a
  single-level target, retain that layout unless native behavior is verified.
- First PNG import should require exact target dimensions and a documented
  8-bit RGBA representation; no silent resizing, vertical flip, premultiplying
  alpha, or profile conversion. Reject unsupported input clearly. Dimensions,
  byte arithmetic, decoded memory, CRCs and image termination need bounds checks.
- DXT5 must not be universally substituted for DXT3. Either implement each
  supported target's encoding or explicitly restrict the first milestone.
- Compression alone does not establish alpha meaning. Determine shader channel
  usage, UV orientation, sampler addressing, color-space handling and mip
  filtering before specifying the final artwork contract. Straight-alpha color
  decal blending is **not yet proven**. The existing C++ preview is approximate.
- Test opaque colors, alpha zero/half/full, colored transparent borders, UV
  corner markers and seams. Test the lowest mip levels and distant race views.
- Validate the rebuilt native index independently against ZIP entries: component
  names, sibling/child links, file indexes, sizes, offsets and CRC32 sum modulo
  2^32. Preserve native format behavior from the existing writer and tests.
  This index uses member CRCs; do not invent a new resource-hash field.
- Refuse path traversal, aliases, symlinks and unrelated output folders. An
  owned output needs a tool-specific ownership record, distinct from any
  runtime requirement. No runtime `mod.json` is required. Publish a complete
  validated pair and test interrupted/repeated export behavior.

## 4. Live verification gate

Record the exact ReRiff loader build, source hashes, selected car, saved pack
index, numeric livery, mod folder, conflicting resource paths and package hashes.
Use a test environment that protects the owner's saves. The game itself may
write settings during selection/racing; "the exporter does not edit saves"
does not imply a live test leaves them untouched.

Required sequence after native lookup and texture binding are established:

1. Capture original ALF livery 1 in garage and race at fixed views.
2. Test the byte-identical package. Check native lookup returns the mod resource,
   since unchanged appearance alone cannot prove the mod was used.
3. Test a small recognizable asymmetric diagnostic edit with color/alpha markers.
   Verify orientation, seams, transparency, lighting and distance mip behavior
   in both garage and race; verify another livery/car remains unchanged.
4. Fully restart and repeat the target selection, including selecting another
   pack and returning, to distinguish caching from persistent replacement.
5. Remove only the owned test mod, fully restart, and verify stock appearance
   returns. Record screenshots/logs and owner verification if this session cannot
   exercise the game. Do not call a successful mount a rendering pass.
