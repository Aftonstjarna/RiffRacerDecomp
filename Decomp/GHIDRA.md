# Native recovery with Ghidra

Run Ghidra inside your development container. Ghidra 12.2 requires Java 25;
set `JAVA_HOME` to a compatible JDK installation and `GHIDRA_HOME` to your
Ghidra installation. Run the examples below from the repository root, inside
the container.

Choose a project directory without dot-prefixed path components. Keep the
Ghidra database outside the source tree; research exports belong in the
repository's ignored `analysis/ghidra` directory.

Initial import (original file remains read-only):

```sh
export GHIDRA_HOME="/path/to/ghidra"
export JAVA_HOME="/path/to/jdk-25"
export PATH="$JAVA_HOME/bin:$PATH"
recovery_project="$HOME/ghidra-projects"
mkdir -p "$recovery_project"
"$GHIDRA_HOME/support/analyzeHeadless" \
  "$recovery_project" RiffRacerNative \
  -import "$HOME/.local/share/Steam/steamapps/common/Riff Racer/Game.exe" \
  -processor x86:LE:32:default -cspec windows \
  -analysisTimeoutPerFile 180 -max-cpu 4 \
  -scriptPath "$PWD/Decomp" \
  -postScript ExportRecovery.java \
  "$PWD/analysis/ghidra/recovery" \
  0048cab0 004a0af0 005282e0 004a22e0
```

Adjust the executable path for your Steam installation. For later exports,
reuse the database:

```sh
"$GHIDRA_HOME/support/analyzeHeadless" \
  "$recovery_project" RiffRacerNative -process Game.exe -noanalysis \
  -scriptPath "$PWD/Decomp" \
  -postScript ExportRecovery.java \
  "$PWD/analysis/ghidra/recovery" 004a22e0 004a1c30
```

Omit `-noanalysis` when more analysis is required. Check the log for timeouts
and decompiler warnings; successful export does not establish complete or
correct program analysis. The initial whole-program analysis reached its
180-second limit, while targeted exports succeeded. Do not treat that partial
analysis as a completed whole-program pass.

One observed inference error matters for recovery: initial decompilation of
0x4A22E0 treated the width passed through ECX to 0x4A1C30 as unaffected, showing
zero horizontal padding. The original helper writes through that width pointer
on one branch. The reconstructed assembly preserves both dimensions and both
centering offsets. Do not promote inferred Ghidra prototypes to ground truth.

`ExportRecovery.java` is a small Ghidra API adapter: it hash-checks the original,
exports selected functions and caller/callee references, and labels the output
as research rather than reconstructed source. Ghidra's C output, inferred types
and boundaries must be checked against original instructions and managed IL.
Only source-generated bytes passing the strict comparator enter coverage totals.

Use ILSpy for managed-code analysis.
